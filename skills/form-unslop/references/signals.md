# The separate unslop checklist

**Provenance:** diagnostic adaptation of user-supplied notes attributed to Charles Liu, `@charles.unemployed`, for “20 AI Design Slop Indicators (in under 30 seconds),” dated 2026-11-03. The reel and caption were not independently retrieved. The supplied selection contains 19 signals because dithering was deliberately omitted. This file is separate from FORM's design-reference catalog.

For new creative work and unslop repairs, start without these ornamental treatments. Exceptions require an explicit approved choice or a necessary task role. The rows' “keep” cases preserve meaning and user intent; they are not permission to decorate every fresh interface. A genre such as “warm bookshop,” “technical,” or “premium” is insufficient justification. Multiple symptoms can have one cause; fix the cause and still inspect every relevant row.

| ID / Signal | Investigate when | Keep when | Specific correction to consider |
| --- | --- | --- | --- |
| U01 Tags & pills | Many labels look interactive or important but add no status, selection, or navigation meaning. | They communicate real status, active filters, selectable entities, or a deliberately chosen brand treatment. | Remove duplicate labels; distinguish interactive chips from static status; reduce competing emphasis. |
| U02 Excessive italics | Each headline has a decorative italic accent without a change in meaning; reading rhythm becomes inconsistent. | Genuine semantic emphasis, quoted text, or an explicitly selected italic style requires it. A book title alone is not a reason to invent italic cover styling. | Use upright type for the starting design; express hierarchy through role, scale, weight, or layout. |
| U03 Instrument Serif | The face is an automatic “tasteful” substitution unrelated to the subject, content, or approved design. | It is explicitly chosen by the user/brand and readable in the actual role. | Compare real-content type specimens; preserve an approved face and fix its role/metrics if necessary. |
| U04 Negative kerning | Tight tracking is added as a display recipe or creates collisions, broken word shapes, or cramped headings. | An approved reference/wordmark requires it and the actual rendering has been checked. | Start with natural tracking. Confirm user spacing overrides preserve content. |
| U05 Over-the-top detailed UI | Decorative micro-panels, fake controls, or invented analytics stand in for product evidence. | A working expert tool needs the detail for comparison, control, or diagnosis. | Remove invented proof; simplify a demonstration to the actual task; preserve necessary density and correct state. |
| U06 Overusing dividers | Every heading, paragraph, and nested region has a rule even though spacing already establishes grouping. | Rows, form regions, comparisons, or a chosen graphic language need a clear boundary. | Remove redundant rules; use proximity and alignment for simple groups; retain boundaries that explain relationships. |
| U07 Color shades & opacities | Near-identical arbitrary shades and faded labels weaken hierarchy, meaning, or legibility. | Semantic surfaces, states, elevation, or a measured color system needs the distinctions. | Consolidate by role and check actual adjacent pairs/states. Never globally increase opacity without reviewing disabled/overlay behavior. |
| U08 Containers with borders | A stack of boxes gives every content fragment the same priority or makes one conceptual group look fragmented. | Inputs, selected objects, regions, tables, or independent cards need boundaries or affordances. | Remove unnecessary wrappers; keep semantic grouping and control boundaries; restore contrast when needed. |
| U09 Overly detailed diagrams | A dense diagram repeats the text, invents connections, or cannot be read at the displayed size. | Genuine system complexity or a technical audience benefits from the relationships shown. | Focus the diagram on one question, use progressive detail, and keep the complete technical view available when required. |
| U10 Verbose, redundant text | An eyebrow, heading, paragraph, and CTA say the same thing in slightly different words. | Precision, legal obligations, learning, or recovery requires the detail. | State the fact once and name the next action. Preserve truth, qualifiers, and necessary recovery information. |
| U11 Code breadcrumbs | File paths, fake code, or version strings decorate an unrelated customer flow. | The interface is a developer tool, file browser, documentation, or source/provenance view. | Replace decorative implementation language with the audience's task language; preserve actual navigation and technical identifiers. |
| U12 Section numbering | “01 / 02 / 03” adds ceremony to sections that have no meaningful order. | Ordered instructions, onboarding, ranking, or an explicitly chosen publication system needs sequence. | Remove ornamental numbering; retain meaningful order and distinguish it from labels/IDs. |
| U13 Eyebrows | A small label repeats its heading or precedes every block as a default scaffold. | It adds a distinct category, content type, status, location, or other useful orientation. | Delete duplication or integrate information into the heading; retain a useful category label. |
| U14 ASCII images | Terminal-like scenery is an unrelated shortcut to a “technical” identity. | Text art, a real terminal context, the subject's medium, or an approved creative direction calls for it. | Choose subject-specific visual evidence or a fitting material; keep the effect when intentional. This signal is not dithering. |
| U15 Squiggles | Underlines/arrows/doodles accumulate without identifying anything useful or expressing the subject. | Real annotation, a hand-drawn identity, or a deliberate visual narrative needs them. | Remove unassigned marks; make useful annotation specific, legible, and connected to its target. |
| U16 Excessive mono fonts | Body copy and unrelated labels become a generic “technical” costume with poor reading rhythm. | Code, identifiers, measurement, or an approved type system benefits from monospace. | Reassign type roles; test body readability; retain technical tokens and tabular information where useful. |
| U17 ALL CAPS subtitles | Small uppercase lines are added as a generic hierarchy or repeated framing device. | An actual acronym, required identifier, or explicitly approved type system calls for uppercase. | Use sentence case supporting text; preserve the meaning of real acronyms/identifiers. |
| U18 Gradient backgrounds | Ambient haze substitutes for a concept, reduces text contrast, or appears unchanged across unrelated sections. | Lighting, material, data, subject matter, or the approved identity gives the gradient a job. | Test a simpler surface; retain the gradient if it improves the composition and verify all relevant background positions. |
| U19 Periods in UI | Every short heading, nav item, and button gains ornamental punctuation that disrupts a consistent voice. | Full sentences, abbreviations, technical identifiers, or deliberate voice require punctuation. | Standardize by text role; preserve sentences, decimal values, versions, filenames, and necessary language conventions. |

## Use the checklist without making everything look alike

Keep actual meaning, required affordances, approved references, and useful density. Prefer a plain status label over adding a dot and pill around it. Prefer a clear action label over adding an arrow. If evidence is missing, verify it. If the feature is outside the authorized scope, report it without silently expanding the work.

## Additional defaults found in FORM's own rejected outputs

These are owner-supplied corrections, separate from the Charles Liu attribution and the 19-row count:

- **Indicator lights:** tiny colored dots beside status, availability, demo, brand, or metadata labels. Do not add them as a visual flourish or imply liveness. Actual status remains readable in words. Native selection controls and genuine data marks are different roles that require their own justification.
- **Arrow glyphs and icons:** repeated `↗`, `→`, chevrons, or drawn arrows attached to ordinary actions, rows, navigation, or artwork captions. Use clear Open, Save, Undo, Redo, and Continue labels. An icon being conventional does not justify adding it beside an already clear label. Keep native disclosure and genuine spatial/map directions when required, or an explicitly selected reference.

Inspect typography and ornaments inside artwork too. An italicized book cover or a decorative arrow in an SVG is still part of the design. Functional tests do not establish that these criteria are met.

After simplification, test whether something valuable disappeared: status recognition, form boundaries, document orientation, comparison density, chosen personality, or an accessible alternative. The result should be more intentional, not merely emptier.
