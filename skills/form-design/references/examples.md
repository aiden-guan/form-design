# Worked translations of a brief

These examples demonstrate decisions, not completed production designs or mandatory templates. Change the visual direction when the content changes.

## A ceramics studio that wants a memorable booking site

**Brief:** “Make our small ceramics studio feel beautiful and welcoming. We need class bookings. We have our own photographs.”

**Direction:** Workbench journal. Warm photographic close-ups carry the personality; measured captions and generous body type make the classes easy to understand. The signature is a relationship between irregular clay forms and precise scheduling information.

**Composition:** A photograph with room for a short studio statement; an immediately legible class summary; instructor/process evidence; dates and a clear booking route. On mobile, choose a new crop and put dates near the class description. Do not assume a pricing grid, testimonial carousel, or large scrolling animation is needed.

**System:** A readable body face and a contrasting display role tested on the studio's actual name; neutral surfaces sampled for harmony with the photos; an action color chosen for contrast. The schedule uses clear selected, unavailable, and loading states.

**Representative slice:** One class, its photograph, dates, and booking selection. Verify the full selection path and touch targets before expanding the page. If booking integration is unavailable, label the prototype and report the missing connection.

**Review:** Can a first-time visitor identify a suitable class and its next step? Are image crops intentional at both sizes? Does keyboard focus remain clear against the photographs?

## A financial operations dashboard that feels considered

**Brief:** “Our reconciliation screen looks cheap. Keep the workflow and existing component library.”

**Direction:** Precise ledger. Improve typographic hierarchy, numeric alignment, grouping, and state clarity within the established system. Keep useful density. Personality can live in a disciplined accent and a clear discrepancy visualization.

**Composition:** Preserve the comparison table and filters. Align comparable amounts, give exceptions a distinct but restrained treatment, and keep the selected account/time range visible. Remove decorative spacing that pushes the primary work out of view.

**Representative slice:** A populated table with one discrepancy, a selected row, and an error/retry state. Check long account names, negative amounts, empty results, and keyboard operation.

**Review:** Does the next action become easier to find? Can someone distinguish a selected row from an error? Do all existing actions still work? Do not replace the app shell or add a new chart library just to make the screen feel designed.

## A playful mobile habit app

**Brief:** “Design a cheerful habit tracker for phones. I want it to feel alive.”

**Direction:** Growing collection. Use a small evolving visual motif linked to completed habits, with friendly type and clear day-by-day progress. Avoid a constant celebratory animation every time the screen opens.

**Composition:** Today and the next habit are primary; history remains easy to reach. Use platform navigation, enlarged-text support, safe areas, and touch feedback. Keep the completion control explicit rather than requiring a hidden swipe.

**Motion:** A brief completion response can acknowledge the action. Frequent list navigation stays immediate. Reduced motion uses a clear state change and the same progress information.

**Representative slice:** Today with multiple habits, completion/undo, no habits, and a sync failure that preserves progress. Use honest local sample data if no backend exists.

**Review:** Is it operable with one hand and enlarged text? Does joy survive with animation disabled? Are streak and status conveyed by more than color?

## A shader-led music festival identity

**Brief:** “Build an experimental festival page with a halftone atmosphere. Tickets and the lineup still matter.”

**Direction:** Night-print signal. A single art-directed rendering provides atmosphere while strong type carries artist names, date, and the ticket action. Pattern scale, tonal range, and crop become the signature.

**Composition:** Establish the event and route to tickets without waiting for a scene. Give the lineup its own reading structure instead of placing all text over the busiest area. Mobile gets a lower-cost/static composition if the effect would compromise usability.

**Reference use:** Search halftone for material and inspect the actual original. Follow any source license; recreate reference-only work in original code. A still is evidence of appearance, not shader parameters or interaction.

**Representative slice:** Initial view and lineup at wide/narrow sizes, effect disabled, slow/missing media, keyboard focus. Measure the renderer before claiming it performs well.

## A request to match a supplied screenshot

**Brief:** “Rebuild this exact page. Keep my text and use the existing stack.”

**Direction:** Fidelity to the supplied target. Identify geometry, type roles, crop, palette, and visible states; record missing assets or fonts. Do not substitute an original art direction because it is more exciting.

**Implementation:** Establish the large relationships first, then adjust type metrics and spacing against equivalent captures. Preserve real text and semantics. If an image cannot be reproduced faithfully, explain the gap and use the closest permitted asset without claiming identity.

**Review:** Compare at the target size and an appropriate narrow size. Test implemented behavior separately. Report the actual fidelity and evidence gaps; do not call an approximate result “1:1.”
