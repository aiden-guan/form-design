# Diagnose generic design without imposing another template

Read this before substantial visual implementation and use it again on the actual output before delivery. The complete, separately installable diagnostic workflow lives in FORM Unslop; this reference keeps the main design skill useful on its own.

## Begin without the tells

Build the hierarchy with actual content, composition, natural type metrics, imagery, color roles, alignment, and useful space. Start without the following decorative defaults. Add an exception only when a user-selected reference/brand requires it or the actual task needs its meaning. An aesthetic adjective, a familiar genre, or “it adds polish” is insufficient justification.

| Supplied signal | Starting point |
| --- | --- |
| Tags & pills | Plain labels and clear controls; shape is not needed to make every category look important. |
| Excessive italics | Upright typography; no italic word or phrase added to enliven a headline or cover. |
| Instrument Serif | Deliberately chosen real-content type roles; no automatic “tasteful” serif substitution. |
| Negative kerning | Natural tracking; no compressed display-wordmark recipe. |
| Over-detailed UI | The real task and honest evidence; no decorative mock controls or analytics. |
| Overused dividers | Group through proximity and alignment; add a rule only for a relationship that needs it. |
| Shades & opacities | A small semantic palette and legible text; no ladder of faded micro-labels. |
| Bordered containers | Unboxed composition; keep necessary input/selection boundaries. |
| Over-detailed diagrams | One useful question per diagram; do not replace a visual concept with a fake technical drawing. |
| Redundant text | State each fact once; each remaining line adds information. |
| Code breadcrumbs | The audience's task vocabulary; retain real technical identifiers in actual technical tools. |
| Section numbering | Unnumbered sections unless sequence is meaningful. |
| Eyebrows | Start with the useful heading; add a separate label only when it conveys distinct necessary context. |
| ASCII images | Subject-specific evidence or artwork instead of a terminal costume. |
| Squiggles | No loose ornamental marks, doodles, or hand-drawn emphasis. |
| Excessive mono | Readable interface/body type; reserve mono for a genuine technical role. |
| ALL CAPS subtitles | Sentence case supporting text. |
| Gradient backgrounds | A deliberate flat surface; use a gradient only for a demonstrated material/data/reference need. |
| Periods in short UI labels | Plain action/navigation labels; preserve supplied sentences and necessary punctuation. |

Two additional defaults were exposed in FORM's own rejected outputs: **indicator lights** and **arrow glyphs**. Do not add colored dots beside labels to suggest activity, availability, or sophistication. Show genuine status in words. Do not append `↗`, `→`, chevrons, or arrow icons to ordinary buttons, links, list rows, or captions. Use clear labels for Open, Save, Undo, Redo, Continue, and similar actions. Calling an Undo icon “conventional” does not make it necessary beside the word Undo. Keep native disclosure affordances and directions that are themselves information, such as spatial/map navigation, when the task requires them.

These two additions come from direct owner feedback, not the Charles Liu attribution. The original 19-signal selection remains separate from the reference catalog, and dithering remains excluded.

## Look for the cause

An interface reads as interchangeable when the same visual recipe survives unchanged after swapping its project name and content. Inspect its reading path, information structure, imagery, voice, and interaction model before tweaking decoration.

Common symptoms include undifferentiated cards, status-shaped labels with no status, tiny faded text everywhere, italic accents with no emphasis to express, or a diagram that repeats a nearby paragraph. They are candidates for investigation, not proof of AI authorship.

For each candidate ask:

1. What job does it do for this audience or subject?
2. Is that job already done by another element?
3. Would removal make the task, hierarchy, navigation, accessibility, or intended expression worse?
4. Is it explicitly chosen by the user or an approved reference?

Preserve required meaning and explicit user choices. A useful status can remain as plain text without its ornamental dot or pill. A control can remain discoverable through its label, position, and state without an appended arrow. Change the composition when that is the actual problem.

## Repair with a specific move

| Cause | Better move |
| --- | --- |
| Every section has equal weight | Establish a reading path and change relative emphasis, grouping, or section structure. |
| Decorative pills repeat the heading | Remove the redundant label; preserve real filters and status indicators. |
| Bordered containers obscure relationships | Use spacing and alignment for simple grouping; retain fields, tables, and boundaries that convey a useful region. |
| The design has no subject-specific material | Use actual work, product evidence, vocabulary, imagery, or process to shape the central composition. |
| “More detail” became an invented interface | Replace fake controls and micro-labels with honest evidence; keep necessary complexity in working tools. |
| A font/color choice feels arbitrary | Compare a few alternatives on the same real content, then implement the selected roles. |
| Copy is long without adding information | State the fact and next action once. Preserve necessary legal, technical, and recovery information. |

## Review the result, including artwork

Inspect the real wide/narrow screen and relevant states, including SVG text, cover artwork, pseudo-elements, and modal contents. Check every row above; record any exception and its concrete reason in the working notes. Remove unsupported additions. Passing interaction tests does not pass this visual review. Do not claim “unslopped,” “polished,” or improved from a count, a build, or a favorable review that overlooked the owner's criteria.

## Preserve useful meaning

Native controls, field boundaries, meaningful sequences, true technical identifiers, and explicitly approved brand choices can have necessary jobs. Keep them when the task requires them. Preserve useful density and personality through composition and subject matter rather than reintroducing the ornamental defaults. Dithering is deliberately outside this checklist; assess it only for a separately demonstrated problem such as legibility or rendering cost.

After a repair, operate the primary task and review the same state/viewport as the original. Check that useful meaning survived. End with the concrete changes, the significant choices preserved, and what remains unverified; do not report a fictional “AI-slop score.”
